# 스레드 세부 학습

### 학습 키워드

`# thread` `# Multi-threading` `# thread pool`

## 1. 핵심 개념

### Thread

스레드는 CPU 이용의 기본 단위입니다.  
스레드는 다음 요소로 구성됩니다.

- 스레드 아이디
- 프로그램 카운터
- 레지스터들
- 스택  
  동일한 프로세스에 있는 다른 스레드들과 코드/데이터 섹션, OS 자원을 공유합니다.

### 멀티 스레딩 장점

1. **응답력 (Responsiveness)**  
   시간이 오래 걸리는 작업을 수행하는 동안에도 사용자의 다른 이벤트에 응답할 수 있습니다.

2. **자원 공유 (Resource Sharing)**  
   프로세스는 공유 메모리나 메시지 전달 같은 기술을 통해서만 자원을 공유할 수 있습니다.  
   스레드는 같은 프로세스 내에 존재하면 동일한 주소 공간을 사용하므로 애플리케이션 단에서 자원을 쉽게 공유할 수 있습니다.

3. **경제성 (Economy)**  
   프로세스 생성에 필요한 메모리와 자원 할당 비용은 큽니다.  
   스레드는 프로세스보다 생성 비용이 작고 문맥 교환도 더 빠릅니다.

4. **확장성 (Scalability)**  
   멀티 코어 시스템에서 여러 스레드를 서로 다른 코어에 분배하여 동시에 실행할 수 있으므로 시스템의 처리 성능을 더 효과적으로 활용할 수 있습니다.

### 멀티 코어 시스템에서 고려해야 할 문제

1. **작업 분배**  
   서로 독립적인 작업으로 나누어 동시 실행이 가능하도록 해야 합니다.

2. **균형**  
   특정 코어에 작업이 몰리지 않도록 균등하게 분배해야 합니다.

3. **데이터 분배**  
   작업들이 사용하는 데이터를 적절한 코어에 배치해야 합니다.

4. **데이터 의존성**  
   여러 작업이 동일한 데이터에 의존한다면 동기화가 필요합니다.

5. **테스트와 디버깅**  
   단일 스레드 환경보다 훨씬 어려워집니다.

### 병렬 처리 방식

- **데이터 병렬화**  
  동일한 데이터를 나누어 여러 코어가 동일한 작업으로 처리합니다.  
  (예: 1부터 10까지의 합을 구할 때 1번 코어가 1-5, 2번 코어가 6-10 담당)

- **작업 병렬화**  
  각 스레드가 서로 다른 작업을 동시에 수행합니다.

실제 시스템에서는 두 방식이 함께 사용되기도 합니다.

### 유저 스레드와 커널 스레드

- **유저 스레드**: 커널 위에서 커널 지원 없이 관리됩니다.
- **커널 스레드**: OS가 직접 관리합니다.

#### Many-to-One

여러 유저 스레드가 하나의 커널 스레드에 매핑됩니다.  
유저 공간에서 스레드 관리가 효율적이지만, 하나의 시스템 콜이 발생하면 전체가 블락됩니다. 또한 멀티 코어의 장점을 활용하지 못합니다.

#### One-to-One

하나의 유저 스레드가 하나의 커널 스레드에 매핑됩니다.  
동시성 이점이 있지만 유저 스레드 수만큼 커널 스레드가 생성되므로 너무 많아지면 성능이 저하될 수 있습니다.

#### Many-to-Many

여러 유저 스레드를 동일하거나 더 적은 수의 커널 스레드에 매핑합니다.  
두 모델의 단점을 보완하지만 구현이 복잡합니다.

현대의 대부분 OS는 현대에서는 시스템 코어의 수가 늘어남과 Many-to-Many 모델의 구현의 복잡성 때문에 **One-to-One 모델**을 사용합니다.

### Implicit Threading

스레드 생성 및 관리를 개발자가 아닌 **컴파일러와 런타임 라이브러리**가 담당하는 방식입니다. 개발자는 작업(task)만 정의합니다.

#### 스레드 풀

작업마다 스레드를 생성하는 비용과 자원 낭비를 줄이기 위한 방식입니다.

- 초기 생성된 스레드들을 풀에 넣어 대기시킵니다.
- 요청이 들어오면 스레드를 할당합니다.
- 작업이 끝난 스레드는 다시 풀로 돌아갑니다.
- 사용할 스레드가 없으면 작업은 큐에서 대기합니다.

스레드 생성 비용을 줄이고 시스템 자원 사용을 제한할 수 있습니다.

#### OpenMP

공유 메모리 환경에서 병렬 프로그래밍을 지원하는 API입니다.  
C, C++, FORTRAN 프로그램을 위한 컴파일러 지시문 형태로 제공됩니다.

#### Grand Central Dispatch (GCD)

macOS와 iOS를 위한 Apple 기술입니다.  
앱의 요구와 시스템 용량에 따라 스레드 개수를 스스로 조절합니다.

- 작업을 **dispatch queue**에 넣습니다.
- GCD가 관리하는 **스레드 풀**에서 스레드를 가져와 작업을 실행합니다.

**Dispatch Queue 타입**

- **Serial Queue**: FIFO 순서로 작업을 처리합니다. 하나의 작업이 끝나야 다음 작업이 시작됩니다.
  - 메인 큐는 직렬 큐이며 UI 업데이트는 반드시 이 큐에서 수행됩니다.
- **Concurrent Queue**: 작업은 FIFO 순서로 꺼내지만 병렬 실행이 가능합니다.

**QoS (Quality of Service)**

1. **User Interactive**
2. **User Initiated**
3. **Utility**
4. **Background**

> **Priority Inversion**  
> 낮은 우선순위 스레드가 높은 우선순위 스레드가 필요한 자원을 점유하면 우선순위 역전이 발생합니다.  
> GCD는 이를 감지하여 일시적으로 우선순위를 높이는 **priority boosting**을 수행합니다.

### 스레딩 이슈

#### [1] fork()와 exec()

- **fork()**
  - 모든 스레드를 복제할 수도 있습니다.
  - 호출한 스레드만 복제할 수도 있습니다.

- **exec()**
  - 모든 스레드를 포함한 전체 프로세스를 새로운 프로그램으로 대체합니다.

`fork()` 이후 바로 `exec()`을 호출하면 호출한 스레드만 복제합니다.

#### [2] 신호 핸들링

이벤트 발생 → 신호 생성 → 프로세스 전달 → 처리 과정으로 이루어집니다.

- 동일 프로세스 내부에서 발생하면 **동기 신호**입니다.
- 외부 이벤트로 발생하면 **비동기 신호**입니다.

비동기 신호는 기본 신호 핸들러 혹은 사용자 정의 신호 핸들러로 처리될 수 있습니다.  
멀티 스레딩을 지원하는 대부분의 UNIX 환경에서, 스레드는 어떤 신호를 받을지 말지를 특정할 수 있습니다. 그래서 신호는 자신을 받는 스레드들에게 전달되어야 하는데, 핸들링은 한 번만 이뤄져야 하기 때문에 처음 발견한 자신을 받는 스레드에게 전달됩니다.

#### [3] 스레드 취소

- **Asynchronous cancellation**: 즉시 종료합니다.
- **Deferred cancellation**: 안전한 지점에서 종료합니다.

iOS에서는 Operation cancel이나 Task cancellation을 통해 cooperative cancellation을 사용합니다.(deferred cancellation 패턴과 일치)

#### [4] TLS (Thread Local Storage)

스레드가 고유하게 가지는 데이터를 의미합니다.  
지역 변수와 달리 스레드 내부 여러 함수에서 사용할 수 있습니다.

### 리눅스의 스레드

리눅스는 프로세스와 스레드를 구분하지 않고 **task**라는 용어를 사용합니다.
리눅스는 **clone() 시스템 콜**로 스레드를 생성합니다.

- **fork()**: 부모의 모든 데이터 구조가 복사됩니다.
- **clone()**: 전달된 플래그에 따라 데이터 구조 대신 포인터를 공유합니다.

`clone()` 호출 시 부모와 자식 작업이 공유할 자원을 플래그로 지정합니다.  
`clone()` 실행 시 새로운 작업이 생성되지만, 플래그에 따라 부모 task의 데이터 구조를 공유합니다.

- CLONE_FS
- CLONE_VM
- CLONE_SIGHAND
- CLONE_FILES
